# Internationalization (i18n)

> **Priority**: #14 in implementation order
> **Scope**: Guard portal only (admin panel is English-only)

## Languages

| Locale Code | Language | Target Audience |
|-------------|----------|-----------------|
| `en` | English | Guards comfortable with English, all admins |
| `hi` | Hindi (Devanagari) | Guards who prefer formal Hindi |
| `hinglish` | Hinglish (Roman script) | Guards who speak Hindi but read Roman letters. Most common in urban India. |

### What is Hinglish?

A natural mix of Hindi and English using Roman/Latin script. It's how most urban Indians text on WhatsApp. Examples:

| English | Hindi | Hinglish |
|---------|-------|----------|
| Submit vacant flat lead | खाली फ्लैट की जानकारी दें | Khaali flat ki info submit karo |
| Do not negotiate rent | किराया तय न करें | Rent negotiate mat karo |
| Owner agrees to receive call | मालिक ने कॉल प्राप्त करने की सहमति दी | Owner ne call receive karne ki permission di |
| Earnings | कमाई | Kamaai |
| Start Visit | विज़िट शुरू करें | Visit start karo |

## Technical Approach

### Library: `next-intl`

Best i18n library for Next.js App Router. Supports:
- Server and client components
- Nested translation keys
- Pluralization
- Date/number formatting
- Static rendering compatible

### Translation File Structure

```
messages/
├── en.json
├── hi.json
└── hinglish.json
```

## Language Selection

### First Login
After password change, guard sees language picker:
```
Choose your language / अपनी भाषा चुनें

[English]  [हिन्दी]  [Hinglish]
```

### Persistent Preference
- Stored in `guard_profiles.language_preference` field (server-side) AND localStorage (client-side fallback)
- Field values: `en` | `hi` | `hinglish`
- On login, read from server. Cache in localStorage for faster subsequent loads.
- Can be changed anytime from Profile page
- Preference persists across sessions

### Middleware
```typescript
// middleware.ts
// Read language preference from cookie/session
// Set next-intl locale accordingly
// Admin routes always use 'en'
```

## What Gets Translated

| Component | Translated? | Notes |
|-----------|-------------|-------|
| Guard nav labels | Yes | All 3 languages |
| Guard form labels | Yes | |
| Guard status badges | Yes | SUBMITTED → "Submit Hua" (Hinglish) |
| Guard rule banner | Yes | Critical — must be clear in guard's language |
| Guard success/error messages | Yes | |
| Admin panel | No | English only |
| Public listing page | No | English only (tenants are usually English-literate) |
| System-generated content (admin notes) | No | Written in English by admin |

## Number & Date Formatting

| Format | English | Hindi/Hinglish |
|--------|---------|----------------|
| Currency | ₹25,000 | ₹25,000 (same — INR symbol universal) |
| Date | Feb 17, 2026 | 17 Feb 2026 |
| Time | 2:00 PM | 2:00 PM (same — 12h format) |
| Phone | +91 98765 43210 | +91 98765 43210 (same) |

Use `next-intl` formatters for consistent locale-aware formatting.

---

## Implementation Notes

1. All user-facing strings in guard portal go through `useTranslations()` hook.
2. Never hardcode strings in guard components — always use translation keys.
3. Admin panel can hardcode strings (English only, simpler).
4. Translation files should be reviewed by a native Hindi speaker before launch.
5. Hinglish translations should sound natural — like WhatsApp messages, not formal translations.
