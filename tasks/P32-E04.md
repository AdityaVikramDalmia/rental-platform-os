# P32-E04: Gamification Layer v1

## Summary

Introduce v3 gamification primitives across OPS/guard personas: XP and level progression, weekly tiers, daily quests, enhanced streak mechanics, and profile widgets. This epic adds new tables, event hooks, cron orchestration, and admin controls for tuning progression behavior.

> All V3 table schemas are canonically defined in F24 (`notes/features/24-incentive-v3-overview.md`). Tasks in this epic reference those schemas - do not redefine table structures.

**Sizing split**: Task system cap is 8 tasks per epic. Execute as two batches: Batch A (T01-T08), Batch B (T09-T15).

**Cron timezone rule**: Convex crons use UTC. All business times are IST (UTC+5:30).

## Tasks

### T01: Schema - Gamification Core Tables

**Description**: Add profile, quest definition, and user quest progress tables for XP and quest tracking.

**Acceptance Criteria**:

1. `gamification_profiles`, `gamification_quests`, and `user_quest_progress` exist with required fields.
2. Indexes support user-persona and active-window quest queries.
3. Table design supports recurring daily quest reset behavior.

**Estimated Effort**: M (0.5 day)

### T02: Constants - Gamification Enums

**Description**: Add weekly tier, badge code, and quest reward type enums/constants.

**Acceptance Criteria**:

1. Enum values are exported with inferred TS union types.
2. Weekly tier taxonomy aligns with v3 spec.
3. Reward type constants support XP/paise/perk flows.

**Estimated Effort**: S (0.25 day)

### T03: Backend - Gamification API

**Description**: Create gamification module for XP awards and profile reads.

**Acceptance Criteria**:

1. `awardXp()` safely updates profile totals and emits level changes.
2. `getProfile()` and `getMyProfile()` return normalized profile payloads.
3. Calls are permission-safe (`gamification.manage` for admin-managed mutation paths, `gamification.view` for read surfaces) and idempotent for retried events.

**Estimated Effort**: M (0.5 day)

### T04: Progression Math - Level Curve

**Description**: Implement deterministic level progression curve and next-level computation helpers.

**Acceptance Criteria**:

1. `xpToNextLevel` is monotonic and deterministic.
2. Level-up transitions handle multi-level jumps from large XP awards.
3. Progress percentage can be computed for UI bars.

**Estimated Effort**: S (0.25 day)

### T05: Integration - XP Event Hooks

**Description**: Wire XP grants to verified lead, completed visit, closure completion, and other specified events.

**Acceptance Criteria**:

1. Lead verified awards 50 XP.
2. Visit completed awards 75 XP.
3. Closure event awards 200 XP.
4. Duplicate/retried events do not over-credit XP.

**Estimated Effort**: M (0.5 day)

### T06: Weekly Tier Engine + Cron

**Description**: Implement weekly tier recalculation and schedule the weekly job at Sunday 18:30 UTC (Monday 00:00 IST).

**Acceptance Criteria**:

1. `recalculateWeeklyTiers()` computes weekly tier by configured thresholds.
2. Cron fires at Sunday 18:30 UTC (Monday 00:00 IST) and updates eligible profiles.
3. Tier history is preserved for profile analytics.

**Estimated Effort**: M (0.5 day)

### T07: Daily Quest Engine + Reset

**Description**: Implement daily quest retrieval, completion flow, and scheduled midnight IST reset.

**Acceptance Criteria**:

1. Users can fetch active daily quests by persona.
2. `completeQuest()` validates target metrics and grants rewards once.
3. Daily reset cron rolls over quest progress at 18:30 UTC daily (00:00 IST next day).

**Estimated Effort**: M (0.5 day)

### T08: Enhanced Streak System with Freeze

**Description**: Add streak freeze inventory and daily streak-preservation checks.

**Acceptance Criteria**:

1. `useStreakFreeze()` consumes freeze only when a break condition exists.
2. Daily checker applies freeze before marking streak break.
3. Freeze usage and remaining count are visible in profile state.

**Estimated Effort**: M (0.5 day)

### T09: Badge Expansion

**Description**: Extend badge definitions and issuance logic using the existing incentive card framework.

**Acceptance Criteria**:

1. New badge codes are defined and mapped to v3 milestones.
2. Existing `incentive_cards` lifecycle remains backward compatible.
3. Badge issuance can trigger from XP/tier/streak milestones.

**Estimated Effort**: S (0.25 day)

### T10: Admin UI - Gamification Tab

**Description**: Build admin controls in `/admin/incentive-settings` for XP map, weekly thresholds, and quest templates.

**Acceptance Criteria**:

1. Admin can edit XP map and threshold config in draft versions.
2. Quest templates can be created/updated/disabled.
3. Validation prevents invalid reward/value combinations.

**Estimated Effort**: M (0.5 day)

### T11: OPS Dashboard Widgets

**Description**: Add gamification widgets for level progress, weekly tier, streak, daily quests, and leaderboard position.

**Acceptance Criteria**:

1. Widgets render with live profile data.
2. Daily quests and streak counters update reactively.
3. Leaderboard view is scoped to relevant persona context.

**Estimated Effort**: M (0.5 day)

### T12: OPS Profile Gamification Section

**Description**: Add profile section showing level, badges, longest streak, and tier history.

**Acceptance Criteria**:

1. Profile shows current level and XP progression.
2. Badge list and longest streak are visible.
3. Weekly tier history is accessible in profile view.

**Estimated Effort**: S (0.25 day)

### T13: Notification Contracts - Gamification Events

**Description**: Define typed notification event contracts for gamification and commission-rate lifecycle signals.

**Acceptance Criteria**:

1. Interfaces exist for level-up, tier change, quest completion, streak-at-risk, and commission rate change events.
2. Contract payloads include recipient, event timestamp, and typed metadata required for future push/inbox delivery.
3. No delivery infrastructure is implemented in this epic; interface definitions only.

**Estimated Effort**: S (0.25 day)

### T14: Property Tests - Gamification Engine

**Description**: Add property tests for deterministic XP, quest, streak, and tier behavior.

**Acceptance Criteria**:

1. Tests validate progression math and threshold transitions under randomized valid XP inputs.
2. Retry/idempotency tests prevent duplicate XP grants or duplicate quest rewards.
3. Edge cases include zero progress windows, single-event users, and all optional gamification modifiers disabled.

**Estimated Effort**: M (0.5 day)

### T15: Cron - Monthly Streak Freeze Refill

**Description**: Add monthly refill cron to enforce minimum freeze inventory for active profiles.

**Acceptance Criteria**:

1. Cron runs on the last day of each month at 18:30 UTC (1st of next month 00:00 IST).
2. Job updates all active profiles with `streak_freezes_remaining = max(current, 1)`.
3. Refill is idempotent and does not reduce existing freeze balances above 1.

**Estimated Effort**: S (0.25 day)

3. Enhanced streak freeze mechanics work without duplicate grants.
4. OPS dashboard/profile surfaces render all gamification widgets.
